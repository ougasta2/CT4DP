# B · Random forest and market clustering

You own two experiments that can run independently. The forest forecasts the
next day's 24 hourly DK1 prices. The Week 6 experiment groups market days using
features available at the assumed forecast cutoff and supplies regime labels for
the team's error analysis.

Run the [shared benchmark](../BENCHMARK.md) with `--model random_forest`. Outputs are in `results/team/random_forest/`.

1. Run the fixed forest in `model.py`. Keep the daily input and 24-output
   interface. Try one change, such as moving `min_samples_leaf` from 5 to 10 to
   test whether more averaging reduces large errors. Make choices on earlier
   data and compare on identical hours. Record annual MAE, eligible ±5% hit
   fractions, negative-price error counts and fit/predict time.
2. Run the fixed four-cluster starter with `python team/b-random-forest/cluster_regimes.py`. It uses
   DK1's previous-day price shape and archived DK1 weather forecasts. Scaling
   and K-means are fit on days before 2023. Today's price, targets and forecast
   errors do not enter the fit.
3. Compare candidate choices of `k` on pre-2023 data using the Davies–Bouldin
   index (lower is better), cluster sizes and interpretable centers. Use
   `--output-dir` for separate local experiment outputs. Explain what the
   clusters represent, and check whether their sizes and error patterns change
   from 2023 to 2024.
4. Share the selected `results/team/random_forest/regimes.csv` with the lead and C through the
   team's approved data route. It contains a unique Copenhagen local date
   (`day`) and an integer `cluster` for each day in 2023–2024. Keep
   `regime_centers.csv` and `regime_diagnostics.csv` for the write-up. Join labels
   to benchmark predictions by local `day` to report error by regime. Use only
   historical predictions to estimate any correction for later evaluation.

Deliver the runnable code, model settings, dates, scores with denominators, and
a paragraph interpreting the forest and clustering results. These are
historical development years and archived inputs have incomplete point-in-time
verification. Keep row-level outputs in the Git-ignored results directory.

## Delivered by B

Decisions: **k = 4** market regimes and the starter forest unchanged
(`min_samples_leaf` = 5, so `model.py` is not modified). All findings are
exploratory: 2023–2024 are development years.

| File | Purpose |
| --- | --- |
| `analysis.ipynb` | Evidence for every choice, with outputs saved: choice of k (Part A), the forest and its `min_samples_leaf` search on a 2022 validation year (Part B), error by regime (Part C), written interpretation (Part D), run record (Part E). |
| `regime_errors.py` | Joins the daily regime labels to the forest's hourly predictions and reports MAE, RMSE and large-error rate by year and regime. A large error is above the 2023 90th percentile of the analysed model's absolute errors. |
| `summary/` | Aggregate tables exported by the notebook (k sweep, leaf search, annual metrics and timing, regime errors, centers, `run_record.json`). |
| `temporaryresults/` | The two row-level hand-off files (`regimes.csv`, `predictions.csv.gz`); temporary, see below. |

Run order, from the repository root with the project environment:

```sh
python scripts/run_team_benchmark.py --model random_forest --data   # about 10 min
python team/b-random-forest/cluster_regimes.py                      # k = 4 labels
python team/b-random-forest/regime_errors.py                        # error by regime
```

Then open `analysis.ipynb` and run all cells. On a fresh clone the notebook also
runs the 2022 leaf search and one extra 2023–2024 run, so the first full run takes
roughly 30 minutes; results are cached under `results/team/`.

Headline results (details and limits in Part D of the notebook): the forest has MAE
21.00 and 18.98 EUR/MWh in 2023 and 2024 and ±5% hit rates of 20.7% and 18.3%. It is
behind the frozen Ridge baseline on MAE and RMSE but slightly ahead on the hit
rate. Regimes 0–2 have similar errors; regime 3 (days after a very expensive day,
only 11 and 18 evaluation days) has the largest, with a large-error rate of 16.7%
and 13.4%.

Row-level files, included **temporarily** for the lead and C to collect, in
`temporaryresults/`:
- `regimes.csv`: daily regime labels (`day`, `cluster`), 731 days in 2023–2024, k = 4, for the Apriori analysis.
- `predictions.csv.gz`: hourly forecasts and actual prices from the starter forest (`min_samples_leaf` = 5), for the ensemble.

The team convention is to keep row-level outputs in the Git-ignored `results/team/`
directory, so the lead should remove `temporaryresults/` once the files are collected.
The same files are regenerated by the run order above. Price and weather data are
adapted from the sources and licences listed in `../DATA_LICENSE.md`.
